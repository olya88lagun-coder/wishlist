# Аналитика активации MyWishList

Счётчик: **112836417**. Настройки целей созданы в действующем кабинете; изменения кода требуют отдельного слияния и публикации. Созданная цель сама по себе не доказывает получение события.

## События и цели

| Событие | Условие отправки | Параметры | ID цели |
|---|---|---|---|
| `auth_completed` | Успешная проверка Telegram Widget, VK или Mini App | `provider`: `telegram`, `vk`, `telegram_miniapp` | 672426855 |
| `wishlist_created` | Список создан в БД; подтверждение доставлено после редиректа | `source`: `finder`, `direct` | 672426921 |
| `wishlist_item_added` | Подарок добавлен в БД | `source`: `finder`, `manual`, `link` | 672426922 |
| `wishlist_link_copied` | `clipboard.writeText` завершился успешно | — | 672426927 |
| `wishlist_reserved` | Server Action бронирования вернул успех | — | 672426929 |
| `guest_wishlist_cta_click` | Нажата ссылка гостевого приглашения | `destination`, `placement`, `signed_in` | 672426934 |

Условия всех шести целей — точное совпадение идентификатора. Ошибка формы, отказ авторизации, ошибка копирования и простой показ страницы не означают успешное действие. Ручное копирование из резервного диалога не измеряется. Открытие мессенджера не считается отправкой сообщения.

`wishlist_item_added` измеряет каждое успешное добавление, а не первый подарок за всю историю профиля. В воронке создания списка первый достигнутый этап добавления показывает первоначальное заполнение. Идентификаторы пользователей/списков для этого не передаются.

## Последовательные воронки

| Название | ID | Шаги в рамках одного визита |
|---|---|---|
| AI — от подборки к сохранению | 672428044 | `gift_finder_result` → `gift_finder_save` |
| AI — первый список после входа | 672427696 | `gift_finder_result` → `auth_completed` → `wishlist_created` → `gift_finder_save` |

Первая воронка подходит и для авторизованных пользователей с готовыми списками. Вторая описывает только путь с входом и созданием списка; её нельзя выдавать за конверсию всех посетителей или за число новых зарегистрированных аккаунтов. Метрика проверяет строгий порядок шагов внутри визита. Исторические агрегаты отдельных целей не заменяют эту последовательность.

## Доставка и минимизация данных

- Тяжёлый скрипт сохраняет `lazyOnload`. `webvisor` остаётся выключенным.
- События ждут готовности счётчика (`triggerEvent`, `yacounter…inited`), а не только появления функции-заглушки `ym`.
- Очередь ограничена 100 событиями и десятью минутами; сохраняется в `sessionStorage` текущей вкладки. При восстановлении документа через bfcache очередь перечитывается, чтобы не повторить уже отправленные события.
- При блокировке `sessionStorage` остаётся очередь в памяти. Перенос между полными загрузками в этом случае не гарантируется. Блокировщик Метрики может полностью запретить доставку.
- Для входа и создания списка сервер записывает короткую cookie `wl_goal_<случайное значение>`. Она доступна JavaScript намеренно: содержит только enum события и параметры, не является credential. Срок — `Max-Age=300`; клиент удаляет её перед постановкой события в очередь. Часы клиента не сравниваются с серверными.
- Для ручного добавления и ссылки Server Action возвращает случайный nonce подтверждения. Он нужен только клиенту для защиты от повторного рендера и не отправляется в Метрику. Формы сохраняют прямые ссылки на Server Actions.
- Передаются только разрешённые ключи параметров. Имена, интересы, названия подарков и списков, заметки, URL, сессии и ID ресурсов в события не включаются. Свободный бюджет нормализуется до суммы либо `custom`.
- Сбор является клиентским и приблизительным. Он не заменяет серверный учёт операций и не обещает строго однократную доставку при любом сетевом сбое или блокировке.

## Проверка после публикации

1. Открыть отдельную вкладку с `?analytics_test=1`. Маркер сохраняется в текущей вкладке; последующие события получают `test_traffic: true`. `?analytics_test=0` выключает маркер.
2. Получить подборку, войти, создать список и сохранить идею.
3. Проверить по одному достижению каждого пройденного успешного этапа. При повторной загрузке страницы auth/list/item-события не должны появляться повторно.
4. Проверить копирование и бронь, отдельно ошибку формы и отказ копирования.
5. В Метрике исключать визиты с параметром `test_traffic=true` из рабочих выводов. Старые тестовые посещения без маркера задним числом не размечаются.

Локальные Playwright-тесты перехватывают все обращения к Метрике и используют синтетический счётчик. Поэтому они проверяют браузерную отправку, порядок и параметры, но не доказывают получение в production-отчёте. Реальные платные AI API в них не вызываются.

Дополнительная проверка с полностью отключённым JavaScript выявила зависание нативного ответа после ручного добавления в локальном Next dev. Оно воспроизвелось и с исходными файлами `master`; операция в тестовой БД завершалась. Исправление этого отдельного поведения и его production-проверка не входят в данный пакет.
