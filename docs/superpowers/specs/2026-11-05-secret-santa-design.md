# Тайный Санта: дизайн

Дата: 5 ноября 2026. Срок запуска: 25 ноября 2026.

## Зачем

Рост трафика к декабрю (см. `docs/growth/2026-11-traffic-plan.md`). Одна игра приводит на сайт сразу группу людей, и каждый становится владельцем вишлиста. Санта открывает желания получателя и уходит в магазин по партнёрской ссылке `/go/`, а это доход.

Успех: игры создаются и доходят до жеребьёвки; участники добавляют желания; часть участников входит через Telegram и остаётся пользователями сайта.

## Кто играет

Коллеги в рабочем чате и компании друзей, 3–30 человек. Многие не захотят входить через Telegram или VK ради игры, поэтому участие без входа обязательно.

## Цели

- Организатор создаёт игру и делится одной ссылкой.
- Участник вступает по имени, без входа, и собирает список желаний теми же средствами, что и обычный вишлист: ссылки из магазинов с фото и ценой, ручное добавление.
- Жеребьёвка по кнопке организатора; каждый видит имя получателя и его список.
- Вход через Telegram — выгода, а не условие: бот присылает результат жеребьёвки и напоминание.

## Не цели

- Запрет пар (муж не вытягивает жену) — решено не делать.
- Вступление после жеребьёвки и перетасовка.
- Чат, анонимные вопросы получателю, сбор денег.
- Платные темы для игры.
- Визуальное оформление: им занимается Codex (см. «Разделение работы»).

## Анти-цели

- Организатор или кто-то ещё узнаёт, кто кому дарит.
- Личная ссылка участника даёт доступ к аккаунту, который потом привязан к Telegram.
- Вход через Telegram ломается или теряет данные у существующих пользователей.
- Участник, вошедший через Telegram с уже существующим аккаунтом, теряет свой список игры.

## Ограничения

- Вход сейчас только через Telegram и VK. Сессия — подписанная cookie (`SESSION_COOKIE`, `verifySession`), без таблицы сессий.
- При входе с активной сессией `loginOrLink` вызывает `linkIdentity(currentUserId, identity)`: новая идентичность привязывается к текущему пользователю. Если идентичность уже принадлежит непустому профилю, возвращается `IDENTITY_TAKEN`.
- `wishlists.owner_id` — NOT NULL, ссылка на `users`.
- Публичный список `/[slug]` закрыт от индексации, показывает брони и партнёрские ссылки.
- Уведомления — через очередь pg-boss (`QUEUES.notify`) и воркер с ботом.
- Локальные e2e-тесты идут на PGlite и при параллельном запуске падают по таймаутам; запускать с `--workers=1`.

## Подходы

Рассмотрены три варианта хранения желаний участника:

- **А. Отдельные таблицы желаний игры.** Проще и изолированнее всего, но желания без фото и цены, без партнёрских ссылок, и участник не становится владельцем вишлиста.
- **Б. Каждый участник получает настоящий вишлист** через анонимного пользователя (строка `users` без `auth_identities`). Работает вся существующая механика списков и партнёрские ссылки. Цена — анонимные пользователи в базе и склейка при входе.
- **В. Сначала как А, при входе превращать в вишлист.** Две модели данных для одного и того же; до входа нет партнёрских ссылок, а большинство не войдёт.

**Выбран Б** (решение владельца проекта): только он даёт и новых владельцев вишлистов, и партнёрские клики.

## Как устроено

### Данные

Новые таблицы (одна миграция):

- `santa_games`: `id`, `organizer_id` → `users` (обязательно с идентичностью), `title` (до 80), `budget_text` (до 40, свободный текст вида «до 1 500 ₽»), `exchange_date` (date), `join_code` (уникальный, случайный, для ссылки вступления), `status` (`open` | `drawn`), `drawn_at`, `created_at`.
- `santa_participants`: `id`, `game_id`, `user_id` → `users`, `wishlist_id` → `wishlists`, `display_name` (до 40), `recipient_participant_id` (NULL до жеребьёвки), `created_at`. Уникально (`game_id`, `user_id`).

`users`: добавить `is_anonymous boolean not null default false`. Анонимный пользователь — без строк в `auth_identities`.

`wishlists.occasion` для списков игры — `new_year`. Название списка: «Тайный Санта: <название игры>».

### Роли и вход

- **Организатор** должен быть вошедшим пользователем с идентичностью. Анонимного пользователя на создании игры отправляем на вход. Организатор тоже участник: при создании игры для него создаётся участник и список.
- **Участник без входа.** По ссылке `/santa/join/<join_code>` вводит имя. Создаются анонимный пользователь, его список и запись участника; выдаётся обычная сессионная cookie этого пользователя. Дальше он «вошедший» для всего существующего кода: редактирует свой список как владелец.
- **Вошедший участник** вступает своим аккаунтом, без анонимного пользователя.
- **Личная ссылка** `/santa/me/<token>`: восстанавливает сессию анонимного участника на другом устройстве или после очистки cookie. Токен случайный, хранится хэшем в `santa_participants`. **Ссылка работает, только пока у пользователя нет ни одной идентичности**; после привязки Telegram/VK она перестаёт действовать (иначе ссылка из чата давала бы доступ к аккаунту). **До жеребьёвки** организатор видит у каждого анонимного участника кнопку «ссылка для возврата», чтобы переслать потерявшему (решение владельца проекта). Кнопка выдаёт отдельный одноразовый токен восстановления, а не личную ссылку участника; токен перестаёт действовать после первого использования и при жеребьёвке. После жеребьёвки кнопки нет. Принятый риск: организатор, который сам откроет такую ссылку до жеребьёвки, сохранит сессию участника и после жеребьёвки увидит его получателя. На странице участника крупно предлагаем сохранить личную ссылку или войти через Telegram.

### Вход анонимного участника через Telegram/VK

Используем существующий `loginOrLink` при активной сессии анонимного пользователя:

1. Идентичность новая → `linkIdentity` привязывает её к анонимному пользователю; снимаем `is_anonymous`. Это уже работает, нужно только снять флаг.
2. Идентичность принадлежит существующему пользователю → вместо ошибки `IDENTITY_TAKEN` для анонимного текущего пользователя выполняем **перенос в одной транзакции**: списки, записи участников, брони и уведомления анонимного пользователя переходят существующему; анонимный пользователь удаляется; сессия выдаётся существующему. Если существующий уже участвует в той же игре (вступил дважды), записи участника не сливаем: переносим только список, а дубль участника удаляем, если жеребьёвки ещё не было; после жеребьёвки — оставляем обе записи и показываем обе (редкий случай).
3. Для неанонимного текущего пользователя поведение не меняется.

### Жеребьёвка

- Кнопка у организатора, доступна при статусе `open` и ≥ 3 участниках.
- Алгоритм: перемешать участников (`crypto.randomInt`, Фишер — Йетс), назначить каждому следующего по кругу. Себе никто не дарит, все получают ровно одного Санту.
- Одна транзакция с блокировкой игры (`FOR UPDATE`): повторное нажатие не перетасовывает.
- После жеребьёвки статус `drawn`, вступление закрыто, удалять участников нельзя.
- До жеребьёвки организатор может удалить участника; список удалённого остаётся у его пользователя.

### Что видят

- **Организатор**: название, бюджет, дату, ссылку вступления, список участников (имя, сколько желаний, вошёл ли через Telegram), кнопку жеребьёвки. Не видит, кто кому дарит.
- **Участник до жеребьёвки**: параметры игры, свой список (переход к редактированию), сколько человек вступило, предложение войти через Telegram.
- **Участник после жеребьёвки**: имя получателя и ссылку на его список `/[slug]` (существующая публичная страница с партнёрскими ссылками); свой список по-прежнему редактируется.
- Список получателя открывается по существующей публичной странице. Чужие участники, кроме Санты, его slug не знают.

### Уведомления

Только участникам с Telegram-идентичностью, через `QUEUES.notify`:

- после жеребьёвки: «Жеребьёвка прошла. Вы дарите <имя>» + ссылка на страницу игры;
- за 2 дня до `exchange_date`: напоминание.

### Аналитика

Новые события через `trackEvent` и цели в Метрике: `santa_created`, `santa_joined` (`signed_in`), `santa_drawn`, `santa_recipient_opened`. Вход через Telegram из игры отличаем параметром `source=santa` у существующего `auth_completed`. Параметры добавить в разрешённые ключи `analytics-events.ts`; имена и ID не передавать.

### Хранение и удаление

- Анонимные пользователи без идентичности и их списки удаляются через 60 дней после `exchange_date` игры (задача в воркере `maintenance.ts`). Игры удаляются там же.
- Обновить `/privacy`: имя участника и его желания хранятся до 60 дней после даты обмена.

### Ограничения от злоупотреблений

- До 30 участников в игре, до 20 игр на организатора.
- Вступление ограничить по `clientKey` (существующий rate-limit).
- `join_code` и токены личных ссылок — 32 случайных байта, base64url.

## Решения исполнителя (после проверки дизайна)

- **Отзыв сессий.** Сессия — подписанная cookie без таблицы, поэтому cookie, выданная по личной ссылке, иначе продолжала бы действовать после привязки Telegram. Добавить `users.session_version integer not null default 0`, класть версию в сессию и сверять в `getCurrentUser` (он уже читает пользователя из БД). Версия увеличивается при привязке первой идентичности к анонимному пользователю и при переносе.
- **Mini App.** Вход через Telegram Mini App не учитывает текущую сессию браузера, но и cookie браузера в него не попадают. Кнопки входа на страницах игры ведут на виджет Telegram и VK в браузере; ссылки в уведомлениях бота ведут на сайт, а не в Mini App. Уведомления получают только уже привязанные пользователи, так что склейка в Mini App не нужна.
- **Что переносится при склейке.** Все ссылки на анонимного пользователя: списки, участники, брони (`guest_user_id`), уведомления об удалении, `notification_log`, `feature_interest`, `design_purchases`. Настройки пользователя (`surpriseMode`, имя, аватар) остаются от существующего аккаунта.
- **Очистка.** Удаляется весь пользователь, если он всё ещё анонимный (нет идентичностей) и прошло 60 дней после самой поздней `exchange_date` среди его игр. Каскад удаляет его списки и брони; это допустимо для анонимного профиля.
- **«Вошёл»** в списке организатора и в аналитике (`signed_in`) — любая идентичность. Уведомления — только при Telegram-идентичности.

## Разделение работы

- **Claude (этот проект)**: миграция, функции в `packages/db`, server actions, маршруты `/santa/new`, `/santa/[id]`, `/santa/join/[code]`, `/santa/me/[token]`, склейка при входе, жеребьёвка, уведомления, очистка, аналитика, тесты. Страницы — с минимальной семантичной разметкой без стилей.
- **Codex**: визуальное оформление этих страниц, точка входа на главной и в подборке `/gifts/secret-santa`. Codex меняет только разметку и стили страниц `/santa/*` и новые компоненты; серверный код, actions и `packages/db` не трогает.

## Оставлено исполнителю

- Точные тексты интерфейса и уведомлений.
- Показывать ли на странице игры фото/цены желаний или только ссылку на список.
- Как вошедший пользователь видит игры в «Моих списках».
- Скрывать ли брони на списках игры от их владельца (существующий `surpriseMode`).

## Для Codex: оформление страниц

Логика готова, страницы свёрстаны минимально, без своих стилей. Codex оформляет только разметку и стили перечисленных файлов и может добавлять новые компоненты и CSS. **Не менять:** `apps/web/src/app/santa/actions.ts`, `join-state.ts`, `me/[token]/route.ts`, всё в `packages/db`, `apps/worker`. Подписи полей и кнопок, перечисленные ниже, используются в e2e-тесте `e2e/secret-santa.spec.ts`: если их меняете, меняйте и тест.

| Страница | Файл | Данные |
|---|---|---|
| Создание игры `/santa/new` | `santa/new/page.tsx`, `CreateSantaForm.tsx` | имя пользователя для подстановки |
| Вступление `/santa/join/<код>` | `santa/join/[code]/page.tsx`, `JoinSantaForm.tsx` | `getSantaJoinInfo`: название, бюджет, дата, статус, число участников |
| Игра `/santa/<id>` | `santa/[id]/page.tsx`, `GameControls.tsx` | `SantaGameView` (`packages/db/src/santa.ts`) |
| Блок «Тайный Санта» в «Моих списках» | `lists/page.tsx` | `listSantaGamesForUser` |

Обязательные элементы:
- Создание: поля «Название игры», «Бюджет», «Дата обмена», «Ваше имя в игре», кнопка «Создать игру».
- Вступление: поле «Ваше имя», кнопка «Вступить в игру»; после вступления — поле «Ваша личная ссылка» (показывается один раз, нужно крупное предупреждение сохранить её) и ссылка «Перейти к игре»; для уже вступивших — «Вы уже в этой игре».
- Игра: «Вы дарите: <имя>» и ссылка «Открыть список получателя» (или «Список желаний получателя удалён»); ссылка «Мой список желаний»; для участника без входа — предложение сохранить личную ссылку и кнопка «Войти»; для организатора до жеребьёвки — поле «Ссылка для участников» (удобно добавить кнопку копирования), у участников кнопки «Ссылка для возврата» и «Удалить», кнопка «Провести жеребьёвку» с подтверждением.
- Организатор не должен видеть, кто кому дарит: не добавлять в его вид ничего, кроме его собственного получателя.
- Точка входа: кнопка «Тайный Санта» на главной и на `/gifts/secret-santa`, ведёт на `/santa/new`.
