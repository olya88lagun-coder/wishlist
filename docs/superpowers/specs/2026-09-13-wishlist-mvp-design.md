# Вишлист-сервис — дизайн MVP

**Дата:** 2026-09-13
**Статус:** согласован в брейншторме, ожидает ревью спецификации
**Рабочее название:** `wishly` (временное, имя и домен выбираются отдельно)

---

## 1. Продукт в одном абзаце

Сервис списков желаний для России/СНГ. Пользователь вставляет (или пересылает боту) ссылку на товар — сервис сам подтягивает название, описание, фото и цену. Можно вести несколько списков, делиться ими, а гости скрыто бронируют подарки. Отличие от аналогов (wishkov.ru, followish.io): Telegram-first удобство (добавление пересылкой ссылки боту, шеринг в чаты, напоминания) и узнаваемый журнальный визуальный стиль.

### Ключевые решения

| Вопрос | Решение |
|---|---|
| Рынок | Россия/СНГ |
| Платформа | Telegram Mini App + бот + веб-сайт (одно Next.js-приложение) |
| Разработка | Соло-разработчик с AI-помощником; бюджет на инфраструктуру ~2–3 тыс. ₽/мес |
| Целевая аудитория | Девушки 18–35, дни рождения и праздники |
| Монетизация на старте | Партнёрские ссылки (CPA) + разовые покупки тем на сайте через ЮKassa |
| Telegram Stars | **Не используются** |
| Вход владельца | Telegram + VK ID (гостям вход не нужен) |
| Визуальный стиль | «Журнал» + игривые детали из «Стикеров» |
| Юр. статус | Самозанятость есть, ЮKassa подключена |

## 2. Модель данных

Одна база и один бэкенд обслуживают бот, Mini App и сайт.

- **User** — id, имя, аватар, настройки (в т.ч. `surpriseMode`), createdAt.
- **AuthIdentity** — userId, provider (`telegram` | `vk`), providerUserId. Уникальность `(provider, providerUserId)`. Один пользователь может привязать оба провайдера.
- **Wishlist** — id, ownerId, title, occasion (`birthday` | `new_year` | `other`), eventDate (nullable), slug (короткий случайный неугадываемый id), themeId, createdAt.
- **Item** — id, wishlistId, sourceUrl, normalizedUrl, store, title, description, imageKey (файл в нашем S3), price (копейки, nullable), currency, parseStatus (`pending` | `ok` | `partial` | `failed`), note, isMustHave, position, deletedAt.
- **Reservation** — id, itemId, guestUserId (nullable), guestToken (для анонимов, cookie), guestName, cancelToken, status (`active` | `cancelled`), createdAt. **Частичный уникальный индекс: одна `active`-бронь на item.**
- **Theme** — id, name, isPaid, price, tokens (JSON: фон, акцент, шрифт заголовка, стиль стикера).
- **Purchase** — id, userId, product (`theme:<id>` | `all_themes`), provider (`yookassa`), providerPaymentId (уникальный), amount, status.
- **ParseCache** — normalizedUrl, result JSON, fetchedAt (TTL 24 ч).
- **AffiliateClick** — itemId, clickedAt, store (для статистики).

### Правила приватности (в `packages/core`, проверяются тестами)

1. API владельца **никогда** не возвращает guestName/guestUserId по его вещам.
2. Владелец видит только флаг «забронировано»; при `surpriseMode = true` — не видит и его.
3. Гости видят «занято» на чужих бронях и свою бронь с возможностью отмены.
4. Владелец не может бронировать вещи в своём списке.

## 3. Основные сценарии

### 3.1 Старт
`/start` в боте → кнопка «Открыть мой вишлист» → Mini App: «Когда твой праздник?» → создаётся первый список. Онбординг — один экран. На сайте: лендинг → вход через Telegram или VK ID → тот же экран.

### 3.2 Добавление подарка
- **Бот:** любое сообщение с URL → «Добавляю…» → сообщение редактируется в карточку (фото, название, цена) с кнопками `[В список ▾] [Изменить] [Удалить]`. Несколько ссылок = несколько подарков. Сообщение без ссылки → подсказка.
- **Mini App / сайт:** поле «Вставьте ссылку на подарок» вверху списка; на десктопе — Ctrl+V на странице списка.
- Карточка создаётся сразу со статусом `pending` (скелетон), клиент опрашивает статус раз в 2 с.
- При `partial`/`failed` интерфейс просит дозаполнить **только недостающие поля** (напр. «Ozon не отдал цену — впишите»).

### 3.3 Шеринг
- **Telegram:** нативный диалог отправки в чат; inline-режим `@бот` в любом чате → выбор списка → превью-карточка.
- **Сайт:** «Скопировать ссылку», VK, **MAX**, Telegram. Если у MAX нет share-URL — кнопка вызывает системный Web Share.
- Для каждого списка генерируется **OG-картинка** в стиле «Журнала»: название, дата, коллаж фото, стикер «осталось N дней».
- Публичная страница `/<slug>` с `noindex`.

### 3.4 Бронирование гостем
Гость открывает ссылку → выбирает подарок → нижний лист: фото, цена, «открыть в магазине ↗», поле имени (в Telegram подставляется), «Маша не узнает, кто дарит» → «Я подарю».
- Гонка двух гостей → второй получает «Упс, уже забронировали» (уникальный индекс).
- Отмена: через бота (кнопка в подтверждении) или на странице (по cookie/cancelToken).
- Владелец удалил забронированный подарок → бот уведомляет гостя (если гость из Telegram).
- Гость с сайта может нажать «Напомнить в Telegram» (привязка через deep link на бота).

### 3.5 Уведомления и напоминания
- Владельцу: «Кто-то забронировал «Свечу»» (не шлётся при `surpriseMode`).
- Гостю: подтверждение брони; напоминания **за 14, 7 и 2 дня** до `eventDate`; уведомление об удалении подарка.
- Анти-спам: не более 2 сообщений одному человеку в сутки (напоминания объединяются в одно сообщение).

## 4. Архитектура

### 4.1 Инфраструктура
Один VPS в РФ (Timeweb Cloud или Selectel), 4 ГБ RAM, ~1,5–2 тыс. ₽/мес. Персональные данные хранятся в РФ (152-ФЗ). Docker Compose:

| Сервис | Назначение |
|---|---|
| `web` (Next.js) | Сайт, Mini App, API, генерация OG-картинок |
| `bot` (grammY, webhook) | Приём ссылок, уведомления, inline-режим |
| `worker` (BullMQ) | Парсинг, загрузка фото в S3, напоминания по расписанию, ежедневный canary парсера |
| `postgres` | Данные |
| `redis` | Очередь и rate limit |
| `caddy` | HTTPS, reverse proxy |
| S3 Timeweb | Фото товаров, ночные бэкапы `pg_dump` |

### 4.2 Структура репозитория (pnpm monorepo)
```
apps/web        Next.js: сайт + Mini App + API
apps/bot        grammY-бот
apps/worker     обработчики очередей и cron
packages/db     схема, миграции, запросы
packages/core   бизнес-правила (брони, видимость, темы, покупки)
packages/parser адаптеры магазинов
packages/ui     токены тем и общие компоненты «Журнала»
```

### 4.3 Аутентификация
- Mini App: валидация Telegram `initData` на сервере (HMAC от токена бота).
- Сайт: Telegram Login Widget и VK ID (OAuth). Сессия — httpOnly cookie.
- Привязка второго провайдера — в настройках аккаунта.
- Гость: анонимный `guestToken` в cookie; в Mini App — Telegram-пользователь.

### 4.4 Парсер
Интерфейс адаптера: `parse(url) → { status: ok | partial | failed, title?, description?, imageUrl?, price?, currency? }`.

Пайплайн:
1. Нормализация URL: раскрытие коротких ссылок, удаление utm/трекинговых параметров, определение магазина.
2. Проверка `ParseCache` (24 ч).
3. Цепочка: **адаптер магазина** → **универсальный OG/JSON-LD/microdata** → **Playwright** → `partial`.
4. Лимиты: 25 с на URL, 1–2 параллельных браузерных контекста, rate limit на домен.
5. Скачивание фото в S3, сохранение `imageKey`.

Стратегии по магазинам (по результатам спайка 2026-09-13, IP дата-центра Timeweb KZ):

| Магазин | Стратегия MVP |
|---|---|
| Wildberries | Название/характеристики/фото — CDN `basket-NN.wbbasket.ru/.../info/ru/card.json`; цена — Playwright |
| Lamoda | Playwright → JSON-LD Product |
| Золотое Яблоко | HTTP с UA мессенджера → OG + microdata `itemprop="price"` |
| Яндекс Маркет | HTTP с UA соц-краулера → OG (название, фото, описание); цена — отдельный адаптер или ручной ввод |
| Ozon | Полуавтомат: название из slug URL, цена и фото вручную. Параллельно исследовать фиды Admitad и тест с RU-VPS |
| Прочие | Универсальный OG/JSON-LD → Playwright → ручное дозаполнение |

**Задача №1 после аренды VPS — повторить спайк с российского IP.** Результаты могут отличаться (особенно WB и Ozon).

### 4.5 Деньги
- **Партнёрские ссылки:** все переходы «в магазин» идут через `/go/:itemId` → запись `AffiliateClick` → редирект на партнёрскую ссылку (Admitad/программа магазина) либо на исходный URL, если партнёрки нет. Сохранённые данные не меняются при смене партнёрской программы.
- **Покупки тем — только на сайте через ЮKassa.** Внутри Telegram (бот и Mini App) нет цен, кнопок покупки и ссылок на оплату — чтобы не нарушать правила Telegram о цифровых товарах. В Mini App показываются только купленные темы.
- Webhook ЮKassa идемпотентен (уникальный `providerPaymentId`); чеки — через ЮKassa для самозанятого.

### 4.6 Надёжность
- Ночной `pg_dump` в S3.
- Логирование ошибок с вырезанием персональных данных.
- Uptime-проверка; при падении и при поломке парсера (canary) бот пишет администратору.

## 5. Визуальная система «Журнал»

- **Палитра:** крем `#F6F1E7` (фон), графит `#2C2C2A` (текст, кнопки), акценты — розовый `#D4537E` (стикер «занято»), жёлтый `#FFE66D` (счётчик дней).
- **Шрифты:** Playfair Display (заголовки, цены, курсив в названии списка) + Manrope (интерфейс). Оба с кириллицей.
- **Mobile-first:** одна колонка на телефоне; на десктопе журнальная сетка 3–4 колонки.
- **Тёмная тема:** по `themeParams` Telegram / `prefers-color-scheme` — графитовый вариант «Журнала», без системного синего.
- **Игривые детали:** стикер «занято» с «шлёп»-анимацией при брони; чуть наклонённый стикер «ДР через N дней». Остальное — спокойно.
- **Темы = наборы токенов** на общей разметке (`packages/ui`). Новая тема не требует новой вёрстки.

Ключевые экраны: «Мой список», «Добавление подарка» (скелетон + дозаполнение), «Гость бронирует» (нижний лист), «Превью в чате» (OG-картинка).

## 6. Монетизация

**Бесплатно:** неограниченные списки и подарки, бронирование, бот, напоминания, базовая тема «Журнал» (светлая и тёмная).

**Платно (разово, сайт, ЮKassa) в MVP:**
| Продукт | Цена |
|---|---|
| Отдельная тема (2 темы на старте, напр. «Минимал», «Романтика») | 99 ₽, навсегда |
| «Все темы навсегда» | 499 ₽ |

**Партнёрские ссылки:** CPA через `/go/:itemId`.

## 7. Границы MVP

### Входит
Вход Telegram + VK ID; несколько списков с поводом и датой; подарки с заметкой и «очень хочу»; парсер (WB, Lamoda, ЗЯ, Я.Маркет, универсальный, Ozon полуавтомат); шеринг (публичная страница, OG-картинка, кнопки, inline-режим); скрытое бронирование без регистрации, отмена, «Полный сюрприз»; бот (добавление, уведомления, напоминания 14/7/2); ЮKassa + 2 темы + «Все темы»; партнёрский редирект; лендинг.

### Не входит (v2+)
«Скинуться» (совместный подарок); отслеживание снижения цены; «Праздничный режим» (свой slug, обложка превью, конфетти, без логотипа); сезонные темы; вход через email и Яндекс ID; ручная drag-сортировка; лента идей подарков; браузерное расширение; резидентные прокси для Ozon; реклама брендов.

## 8. Порядок разработки (~6–8 недель)

1. Повтор спайка парсера с российского IP на имеющемся VPS (VPS уже арендован).
2. Фундамент: монорепо, схема БД, auth Telegram + VK, автодеплой.
3. Списки и подарки (ручное добавление), UI «Журнала».
4. Воркер парсинга и адаптеры магазинов.
5. Шеринг, гостевое бронирование, OG-картинки.
6. Бот: ссылки, уведомления, напоминания, inline-режим.
7. ЮKassa, темы, партнёрский редирект, лендинг.
8. Закрытая бета (20–30 человек) → исправления → публичный запуск.

## 9. Тестирование

- **Unit (TDD)** для `packages/core`: одна активная бронь; владелец не бронирует своё; видимость броней; `surpriseMode`; доступ к темам по покупкам.
- **Тест приватности:** ответы API владельца не содержат данных гостя.
- **Парсер:** фикстурные тесты на сохранённых HTML/JSON каждого магазина; ежедневный canary на 1 реальной ссылке на магазин с алертом в бот.
- **E2E (Playwright):** создать список → добавить подарок → поделиться → забронировать гостем → отменить.
- **Платежи:** идемпотентность webhook ЮKassa (повторный webhook не выдаёт покупку дважды), проверка в тестовом режиме.
- **Продуктовые метрики:** доля списков с ≥3 подарками; доля списков, которыми поделились; доля списков с бронями; конверсия в покупку темы; CTR `/go`.

## 10. Риски и открытые вопросы

| Риск | План |
|---|---|
| Антибот маркетплейсов меняется, парсер ломается | Многоуровневый пайплайн, ручное дозаполнение всегда доступно, ежедневный canary |
| Ozon недоступен с серверных IP | Полуавтомат в MVP; исследовать фиды Admitad, тест с RU-VPS, при спросе — резидентные прокси |
| Правила Telegram о цифровых товарах | Никаких покупок и ссылок на оплату внутри Telegram; сверить актуальные правила перед запуском |
| Маркировка рекламы для партнёрских ссылок | Уточнить у Admitad (erid/ОРД) до включения `/go` с партнёрками |
| Какие магазины (WB, Ozon) доступны в Admitad | Проверить до этапа 7 |
| Наличие share-URL у MAX | Проверить на этапе 5; фолбэк — Web Share API |
| 152-ФЗ | Хостинг и S3 в РФ; политика конфиденциальности и согласие на обработку ПДн на сайте |
