# Task 7: Еженедельный разбор беты

**Files:**
- Create: `docs/beta/weekly-review.md` (дополняется каждую неделю)

**Interfaces:**
- Consumes: `/stats`, пересланные отзывы, логи прода, «Найдено» из чек-листа.
- Produces: запись недели и список исправлений на следующую неделю.

Раз в неделю (например, в понедельник) — 30 минут вместе с ассистентом. Выполняется 3–4 раза за бету.

- [ ] **Step 1: Шаблон**

`docs/beta/weekly-review.md`:
```markdown
# Бета: еженедельные разборы

## Неделя N (YYYY-MM-DD)

### Цифры (`/stats`, за 7 дней и всего)
| Показатель | Значение | Прошлая неделя |
|---|---|---|
| Новых пользователей (всего) | | |
| Новых списков (всего) | | |
| Доля списков с 3+ подарками | | |
| Доля списков с бронями | | |
| Броней за неделю | | |
| Переходов в магазин (по магазинам) | | |
| «Хотят оформление» | | |

### Отзывы (без имён)
- …

### Ошибки прода
- canary: …
- проверка сайта: …
- `error` в логах: …

### Решения
| Проблема | Приоритет | Что делаем | Кто/когда |
|---|---|---|---|
```

- [ ] **Step 2: Ход разбора (каждую неделю)**

1. Пользователь присылает вывод `/stats` и пересланные за неделю отзывы (можно скриншотами; имена ассистент в документ не переносит).
2. Ассистент после «да» снимает ошибки с прода:
```bash
ssh root@200.169.178.231 'docker logs --since 168h wishlist-worker-1 2>&1 | grep -E "\"level\":\"error\"" | cut -c1-220 | sort | uniq -c | sort -rn | head -15; docker logs --since 168h wishlist-web-1 2>&1 | grep -iE "error" | grep -v "Server Reference ID" | cut -c1-200 | sort | uniq -c | sort -rn | head -15'
```
3. Заполнить неделю в `docs/beta/weekly-review.md`; для каждой проблемы — приоритет (P1/P2/P3 как в чек-листе).
4. P1 — исправить в ту же неделю отдельными ветками `fix/…` (тест, мерж с согласия, деплой с «да»). P2 — выбрать не больше трёх на неделю. P3 — в бэклог.

- [ ] **Step 3: Commit после каждого разбора**

```bash
git add docs/beta/weekly-review.md
git commit -m "docs: beta week N review"
git push
```
